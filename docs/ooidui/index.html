OoidUI and Swift

Status: early. OoidUI isn’t ready to build on yet. This page will grow into a guide as it reaches its first version.

OoidOS’s own apps are written in C++ against the desktop’s Ooidget kit. Third-party apps can also be written in Swift, with OoidUI: a layer in the manner of SwiftUI, where a view is a value and the screen is updated by fine-grained signals when the state a view reads changes.

How it fits together

  • OoidKit is the desktop kit as a C API, libooidkit.so. An app gives it a tree of nodes (stacks, text, buttons, toggles, text fields and editors, sliders, pickers, lists, split views), then only small patches to that tree as its state changes. It hears the app’s events back: clicks, changes, keys, focus, menu commands, the appearance. It also carries the app’s menus on the global menu bar, its timers, keyboard focus and its accessible tree. Every language uses this one API.
  • OoidUI is the Swift package on top of it: SwiftUI’s way of writing views, in Swift itself, with nothing of our own to keep up beyond the package.
  • The Swift runtime ships once, as a framework every app links to (about 8.5 MB), so an app bundle carries only the app.

How it performs

The sample app, Notes, written in Swift with OoidUI and in C++, measured the same way:

Lines185271
App time per keystroke0.9 ms8 to 98 ms
Memory at rest71 MB61 MB

Because OoidUI updates only what a change touches, a keystroke costs the app under a millisecond.

What comes next

  1. OoidKit first, as every language shares it: its API frozen as version 1, its host moved into the desktop’s repository, drawing only what changed, the screen reader’s bridge wired to it, and scroll views, forms, sheets, images, several windows, drag and drop and translations.
  2. OoidUI version 1: the rest of SwiftUI’s common surface.
  3. Swift in the build: osb recipes for swift-runtime (in the system image, x86_64 and arm64) and swift-toolchain (for developers), plus OoidKit as a framework.
  4. An SDK: the toolchain, OoidKit’s headers, OoidUI as a Swift package, and ooid new app --swift templates.
  5. Docs: the OoidKit reference and an OoidUI guide, with Notes and a gallery of the controls as samples.

To do: a first “your first OoidUI app” guide, once OoidUI and the SDK are ready to use.
