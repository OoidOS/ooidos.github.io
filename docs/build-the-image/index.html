Build the image yourself

Build the OoidOS live image from source, test it in a virtual machine, then write it to a USB stick.

See The repositories for source availability.

What you need

  • A Linux computer, or WSL2 on a PC that runs another system. The build tool, osb, runs as root.
  • python3, git and debootstrap on that computer. osb uses them to set up its own build environment.
  • Disk space: at least 60 GB free. 100 GB is comfortable if you keep several images around.
  • Time: a first build takes most of a day on a fast 16-core PC, and longer on smaller machines. Later builds only redo what changed, so they’re much quicker.
  • An internet connection for the first build, to download the sources.
  • To test the image: QEMU (qemu-system-x86) and OVMF, its UEFI firmware.

1. Get the source

Put ooid-os and ooid-desktop side by side. Put the two Ooidget checkouts inside ooid-desktop/external/.

RepositoryWhat it is
ooid-osThe distribution: osb, the recipes for every package, and the files the system installs
ooid-desktopThe desktop and its apps
ooidget-native and ooidget-coreThe library that draws the desktop and apps

2. Set up the build host

Open a root shell (on WSL2: wsl -u root), go into the ooid-os folder, and run:

This creates the Debian environment used for the build. By default the working directory is /srv/ooidos. To use another disk, set OSB_WORK before you start and keep it set for each command.

3. Add the desktop’s code

From ooid-os, run the snapshot helper to pin the desktop and Ooidget from your local checkouts.

The helper records each snapshot’s checksum in sources.lock. Run it again when the checkouts change. To refresh only the desktop snapshot, run ./osb snapshot ooid-desktop ../ooid-desktop.

4. Download the sources

This downloads every source listed in sources.lock and checks each one against its SHA-256. You can skip this step, since osb build fetches whatever’s missing, but it’s handy to get the downloading done in one go.

You can stop the build and start it again at any time. It picks up from where it left off, and reuses every package it’s already built.

6. Make the live image

This writes the live image to /srv/ooidos/images/ooidos.iso, or to images/ooidos.iso under your chosen work directory.

7. Try it in QEMU

Before you write a stick, it’s worth starting the image in a virtual machine:

OoidOS should start straight into the live session. For an automatic check that it starts and its services run, use tools/boot-test.py /srv/ooidos/images/ooidos.iso from the ooid-os folder.

8. Write it to a stick

Copy ooidos.iso to the computer you’ll write the stick on, then follow Writing the USB stick.

If something goes wrong

  • A step fails. Each step writes a log to /srv/ooidos/logs/<stage>/<step>.log. Read the end of it, fix the cause, and run ./osb build again. Only the stage that failed, and what comes after it, is built again.
  • “sha256 mismatch”. A download changed or got cut short. The bad file is deleted, so just run ./osb fetch again. If it keeps happening, the source’s server may be having trouble.
  • “a snapshot of a local checkout, not here”. You skipped step 3 for that repository. Run the ./osb snapshot line it names.
  • You run out of disk space. Move the work folder to a bigger disk with OSB_WORK, and run ./osb host again there.
  • QEMU is very slow, or says KVM isn’t available. Turn on virtualisation in your computer’s firmware settings, and check that /dev/kvm exists.
  • “Permission denied” or mount errors. osb needs to run as root.

To learn what each stage builds and how osb keeps builds reproducible, see How the build works.
