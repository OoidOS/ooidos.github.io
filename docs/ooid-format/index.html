The .ooid format

OoidOS hands everything out in one kind of file, the .ooid: an app, a framework, a command-line tool or an installer package. A reader knows it by its header (the bytes OOID), not by its name.

What is inside

Every .ooid starts the same way:

  1. A fixed header of 64 bytes: the magic OOID, the format version, the kind, and where the rest is.
  2. A manifest, in JSON: what it is (its id, name, version and build), its licence and whether it may be passed on, where it came from, and each body’s size and SHA-256.
  3. A slot for a signature: an ed25519 signature over the header and the manifest. Because the manifest lists every body’s checksum, the signature covers the whole file.
  4. One body per processor architecture: x86_64, aarch64, or a single any.

The kind decides what a body is:

KindBodyOpening itInstalling it
appa read-only image (squashfs, zstd)mounts it and shows its window: drag the app to Applicationscopies the bundle into /Applications (or ~/Applications)
frameworka read-only imageQuick Look shows itinto /Library/Frameworks/<id>.framework/Versions/<v>, with Current pointing at it
clia read-only image holding name.toolQuick Look shows itinto /Library/Tools/, its commands linked into /usr/local/bin, its man pages and shell completions likewise
packagean archive (tar, zstd)Quick Look shows what it will install where, and whether it needs an administratoras an administrator: its files put in place, with its scripts before and after

Images are mounted where they are, from their offset in the file, never unpacked. An app’s window is laid out by its maker in a .layout.json.

Universal files

A file can carry a body for each architecture, so one file serves every processor. OoidOS mounts or installs the running computer’s body alone, and refuses a file that has none for it, before reading anything else. Files and Quick Look say which it is: “OoidOS App (Universal)”, “(ARM)”, “(Intel and AMD)”.

Signatures and trust

A computer trusts the public keys in /System/Library/Keys (OoidOS’s own channel) and /Library/Keys (added by an administrator). Before an .ooid is mounted or installed, its signature, if it has one, is checked:

  • a bad signature refuses the file;
  • a good one by a key the computer does not trust is shown as signed by an unknown key;
  • an unsigned file is allowed, locally.

Receipts

Every install leaves a receipt and a bill of materials, a list of every file and link it put down, in /Library/Receipts (or ~/Library/Receipts). Removing an app or tool removes exactly what its bill lists.

The ooid command makes, checks, signs, installs and removes .ooid files. The full byte layout is in the ooid tool’s README in the desktop’s repository.
